## 浮层「去设置 API Key」点击无效
- 根因：`retryBtn` 的 click 处理写死 `startExplain()`，不管按钮文案是「解释」「重试」还是「去设置 API Key」都重发请求；`openSettings()`（发 `open-options` 给后台 → `chrome.runtime.openOptionsPage()`）从未被调用。
- 修复：按钮加 `dataset.action`，`no_key` 时设 `"settings"`、其余设 `"retry"`，点击按它分发。commit `fc2ec81`。

## 导出 HTML 的隐藏元数据（不勾选项也不丢字段）
- 诉求：没勾「时间/来源页面/页面地址」时，导出的 HTML 也要带上这些值、只是不显示，好让另一台电脑导入时不丢。
- 实现：`metaAttrs()` 给每张卡片写 `data-id / data-time / data-page-url / data-page-title / data-extract`；聚合卡片只在卡片头写来源，条目继承；`parseFromDom` 优先读这些属性，缺失才回退 `.item-time` / `.item-src` 文本解析（旧版导出文件仍可导入）。
- `data-context` 曾一并写入，确认界面与功能都不使用后删除（HTML 导入路径上 context 一律为空，JSON 备份里仍完整）。
- 验证：本地 HTTP 服务 + 页面内 fetch 回传，headless Chrome 跑真实 `history.js`；时间/来源/地址三选项全关、备份也关时生成的卡片，反解析后字段与源数据逐项一致。commit `fc2ec81`。

## 导出 HTML 的打印按钮
- 标题栏最右加「打印」按钮（`.h1-btn`，与历史页「导出 MD」同款 ghost 风格：无边框、`var(--primary-soft)` 底、`var(--primary)` 字），点击 `window.print()`；`@media print{.h1-btn{display:none}}` 保证打印时不出现。commit `8f61d6d`。
- 中途加过并排的「保存 PDF」（`30617a0`），因行为与打印完全相同被删除，最终只留一个按钮（`e394ae0`）。
- 结论：网页无法编程指定打印目标。`chrome.printing` 仅 ChromeOS 企业；`chrome.debugger` + CDP `Page.printToPDF` 可行但要"调试所有页面"授权 + 顶部横幅；前端 PDF 库（html2pdf/jsPDF+html2canvas）要内联约 1.5 MB、中文需嵌字体、文字变图片。靠 Chrome 记住上次选择的打印目标即等于"默认另存为 PDF"。

## 验证方式与踩坑
- `chrome --headless --dump-dom` 返回 0 字节（`--headless=new` + 独立 `--user-data-dir` 同样失败），改用本地 HTTP 服务 + 页面内 `fetch('/result?data=…')` 回传，配合 `--screenshot` / `--print-to-pdf` 验证。
- 给 history.js 造假 `chrome` 对象时，`storage.local.get` 要按 string / array / object 三种入参分别处理；直接把数组丢进 `Object.assign({}, keys)` 会把键变成 0、1。
- 大文件多段替换仍用独立 python 脚本，改完读回校验；`Edit` 对 content.js 曾出现"返回成功但未落盘"。
